發布 OpenSource Apps Academy 到 GitHub Pages

一般使用：不用終端機

先將整個 ZIP 解壓縮，再雙擊最外層 index.html。不要在壓縮檔預覽視窗內開啟 HTML。目錄、719篇論文導讀與瀏覽器工具不需要 Python、SciPy 或虛擬環境。手機和平板建議使用發布後的 HTTPS 網址，因為部分系統的檔案預覽器不會執行本機 JavaScript。

第一次發布

  1. 在 GitHub 登入 kuonanhong，建立新的 OpenSource_Apps_Academy repository。一般免費帳號請選 Public。不要將模型權重、個人文件或金鑰加入公開網站。

  2. 電腦先裝好 Git 並設定 GitHub SSH 金鑰；執行 ssh -T git@github.com 檢查 GitHub 回覆的帳號是否正確。該測試即使顯示驗證成功，也可能回傳非零退出碼，GitHub 不提供互動式 shell。 若 Git 尚未設定提交身分，先設定 git config --global user.name "您的名稱" 及 git config --global user.email "您的GitHub已驗證信箱"。請填自己的資料，不要照抄範例文字。

  3. 在解壓縮後專案資料夾開啟終端機，先預覽：

    bash Publish_GitHub_Pages.sh

  4. 確認來源及目的地正確後上傳：

    bash Publish_GitHub_Pages.sh --execute

  5. 開啟該 repository → Settings → Pages → Build and deployment。Source 選 Deploy from a branch，Branch 選 main，Folder 選 /(root)，再按 Save。

  6. 等待 Pages 顯示成功及網站網址。預設位置為 https://kuonanhong.github.io/OpenSource_Apps_Academy/。這個網址只有在您完成上傳與 Pages 設定後才會生效。

這個簡化流程把 dist/ 的內容上傳至遠端根目錄；因此 Pages 必須選 /(root)，不能選 /docs 或 /dist。.nojekyll 已附上，讓套件的 vendor/、資料與 HTML 直接發布。若改用 GitHub Actions 發布，需另設定 workflow；本流程不依賴自製 workflow。

日後增量更新與斷線續傳

替換本地套件中新增或修正的檔案後，再執行同一個 --execute 指令。腳本比較檔案內容、分批 commit/push；已完成批次會保留。它不會 force-push，不會自動刪除遠端舊檔，也不會把公開網站與私人權重混在一起。Git 的未完成 pack 可能重傳，不是每個位元組都能續傳。

上傳完整原始碼

預設上傳可直接部署的 dist/。若另建專門保存完整原始碼的 repository，可使用：

bash upload_github.sh --repo git@github.com:kuonanhong/OpenSource_Apps_Academy_Source.git --source . --execute

不要對既有的馬蓋先或華佗 repository 執行此指令，除非您確定要把此專案合入它們。

模型與權重：另一個私人 repository

先安裝 GitHub CLI gh 並執行 gh auth login，供腳本確認 repository 確實是私人；實際傳輸仍走 SSH。再執行：

bash Publish_GitHub_Pages.sh --models-dir "$PWD/models" --models-repo git@github.com:kuonanhong/PRIVATE-MODELS.git --execute

將 models 改成您實際存放權重的資料夾。模型按40MiB分片，附分片與整檔SHA-256；只上傳已取得使用及散布權利的模型。還原方法見 UPLOAD_GUIDE.md。網頁不會因為權重存在 GitHub 而自動執行模型；生成式問答仍需要可用的模型服務。

私有庫與手機使用

GitHub Free 的 Pages 使用公開 repository；其他方案可支援私人 repository。私人 repository 不代表發布的 Pages 網站也是私人。一般 Pages 網站是公開網址。網站發布後，手機、平板、Mac、Windows、Linux 可用瀏覽器開啟；Python/CAD/本機模型不能在 GitHub Pages 的靜態主機內執行。
